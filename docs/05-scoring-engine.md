# Opportunity Scoring

Version: Draft 1

---

# Purpose

Opportunity Scoring evaluates available opportunities and produces normalized attractiveness scores.

It is responsible for ranking opportunities.

It is not responsible for:

- portfolio construction
- position sizing
- execution
- risk response

Opportunity Scoring answers:

"How attractive is this opportunity?"

It does not answer:

"How much capital should be allocated?"

# Responsibilities

Opportunity Scoring:

- evaluates opportunities
- consumes normalized protocol metrics
- ranks protocols
- produces comparable scores
- applies penalties
- applies incentives

Opportunity Scoring consumes precomputed Trust and Liquidity outputs.

It does not own Trust Scoring or Liquidity Scoring logic.

The output must be protocol-agnostic.

---

# Design Philosophy

V1 Opportunity Scoring is deterministic.

No AI.

No machine learning.

No opaque decision systems.

Every score should be explainable.

Every score should be reproducible.

---

# Core Objective

Identify opportunities that maximize:

- capital efficiency
- yield generation

while minimizing:

- risk

# Opportunity Definition

An opportunity represents a deployable capital destination.

Examples:

```text
Aave USDC

Morpho USDC

Moonwell USDC

Aerodrome Stable Pool
```

Each opportunity receives an independent score.

---

# Scoring Model

Conceptual Formula:

score =
(APY × normalizedLiquidityScore × normalizedTrustScore)

---

(risk_penalty + gas_penalty)

---

This formula is illustrative.

The implementation may evolve.

The architecture should support replacing scoring logic without affecting downstream systems.

---

# Core Components

---

# APY Factor

Measures expected return.

Examples:

```text
3.5%

5.2%

7.1%
```

Higher APY increases score.

---

# Normalized Liquidity Score

Consumes Liquidity Scoring output.

Liquidity Scoring owns evaluation of:

- withdrawal delay
- lockups
- withdrawal queues
- redemption accessibility
- market depth

Higher precomputed `normalizedLiquidityScore` increases the opportunity score.

---

# Normalized Trust Score

Consumes Trust Scoring output.

Trust Scoring owns evaluation of:

- protocol maturity
- TVL
- operational history
- audit history

Trust Scores are generated by Trust Scoring.

Opportunity Scoring does not recalculate Trust Scores.

Higher precomputed `normalizedTrustScore` increases the opportunity score.

---

# Risk Penalty

Consumes Risk Engine output.

Examples:

- protocol risk
- concentration risk
- stablecoin risk

Higher risk reduces score.

---

# Gas Penalty

Measures operational friction.

Examples:

- transaction cost
- rebalance cost
- expected execution overhead

Higher costs reduce score.

---

# Policy-Aware Scoring

Scores are influenced by the active Portfolio Policy.

The same protocol may receive different scores for different users.

---

# Example

User A:

```text
selectedProfile = Conservative
riskLimits.minTrustScore = 85
liquidityRequirements.minLiquidityScore = 85
```

---

User B:

```text
selectedProfile = Yield Focused
riskLimits.minTrustScore = 65
liquidityRequirements.minLiquidityScore = 65
```

---

The resulting rankings may differ significantly.

---

# Intent Multipliers

Example:

Conservative Users

Increase weight of:

- trust
- liquidity

Reduce weight of:

- yield

---

Return Preference-Oriented Users

Increase weight of:

- APY

Reduce weight of:

- liquidity

---

Balanced Users

Apply neutral weights.

---

# Scoring Normalization

Opportunity Scoring expects comparable inputs from upstream systems.

Target Range:

```text
0.0
to
1.0
```

This prevents any single metric from dominating the score unexpectedly.

Trust Scoring and Liquidity Scoring define their own score generation models.

---

# Example

```text
APY Score         0.80

Liquidity Score   0.90

Trust Score       0.95

Risk Penalty      0.20

Gas Penalty       0.05
```

---

Result:

```text
Composite Score

0.73
```

---

# Explainability Requirements

Every score must be decomposable.

Users should be able to inspect:

- APY contribution
- liquidity contribution
- trust contribution
- risk deductions
- gas deductions

# Ranking Output

Opportunity Scoring produces opportunity rankings:

```typescript
ScoredOpportunity {

  protocolId: string

  asset: string

  score: number

  scoreBreakdown: object

}
```

Opportunity Scoring does not produce Portfolio Allocation.

---

# Rebalancing Awareness

Opportunity Scoring should avoid encouraging insignificant reallocations.

Example:

Current Opportunity:

```text
Score = 84
```

Potential Opportunity:

```text
Score = 85
```

Difference:

```text
1 point
```

Likely insufficient to justify a rebalance.

---

The Portfolio Construction Engine should consider switching costs.

---

# Hysteresis Principle

Laminar should resist unnecessary movement.

Small score differences should not trigger reallocations.

---

Goal:

Reduce churn.

Reduce gas consumption.

Improve stability.

Opportunity Scoring does not:

- allocate capital
- size positions
- rebalance portfolios
- execute transactions
- classify risk events

---

# Success Criteria

Opportunity Scoring succeeds when:

- scores are explainable
- rankings are stable
- rankings reflect user intent
- rankings produce superior portfolio outcomes

---

# Failure Criteria

Opportunity Scoring fails when:

- rankings become opaque
- score changes create excessive churn
- identical scores are produced for clearly different opportunities
- users cannot understand score rationale

---

# Architectural Principle

Opportunity Scoring should remain simple enough to be trusted.

Complexity should only be added when it produces measurable improvements in portfolio outcomes.

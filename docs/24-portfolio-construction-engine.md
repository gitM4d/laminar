# Portfolio Construction Engine

Version: Draft 1

Status: Core Business Logic

Priority: Critical

---

# Purpose

This document defines how Portfolio Construction transforms active Portfolio Policy, opportunity rankings, and eligible opportunities into portfolio allocations.

This is the core intellectual engine of Laminar.

Everything else in the protocol exists to support, execute, monitor, or explain the decisions defined here.

---

# Core Principle

Users should never need to think about:

* protocols
* pools
* vaults
* APYs
* liquidity sources

Users define:

```
Risk

Liquidity

Return Preference
```

Laminar determines:

```
Portfolio Construction

Protocol Selection

Allocation Weights

Rebalancing Decisions
```

---

# Construction Philosophy

Laminar V1 uses:

```
Target Exposure Model
```

---

Users do not choose protocols.

Users choose outcomes.

---

Example

User says:

```
Low Risk

High Liquidity

Medium Return Preference
```

Laminar determines:

```
Conservative Lending Exposure
```

and builds the portfolio accordingly.

---

# Construction Pipeline

Portfolio construction follows:

```
User Intent
↓
Normalization and Mapping
↓
Selected Profile
↓
Portfolio Policy
↓
Opportunity Discovery
↓
Trust Scoring
↓
Liquidity Scoring
↓
Risk Engine
↓
Opportunity Scoring
↓
Portfolio Construction
↓
Portfolio Allocation
↓
Execution
```

Every stage must be deterministic.

---

# Step 1

Intent Collection

User provides:

```
Risk (1-10)

Liquidity (1-10)

Return Preference (1-10)
```

---

Example

```
Risk              = 3

Liquidity         = 8

Return Preference = 5
```

## Return Preference

Return Preference is not a target APY.

It is not an instruction to select the highest-yield protocol.

It represents the user's willingness to pursue higher expected returns.

Portfolio construction evaluates Return Preference together with Risk and Liquidity.

---

# Step 2

Normalization and Mapping

Raw user inputs are normalized.

Example:

```
Risk              = Low

Liquidity         = High

Return Preference = Medium
```

---

Selected Profile is generated by Normalization and Mapping.

# Step 4

Portfolio Policy

Portfolio Policy is generated after profile classification.

Portfolio Policy defines:

```
Risk Limits

Liquidity Requirements

Target Exposure

Allocation Constraints
```

---

Portfolio Policy is consumed by Portfolio Construction.

---

Policy values are versioned and immutable.

---

# Step 5

Opportunity Discovery

Laminar reads opportunities from:

```
Morpho

Aave

Moonwell

Aerodrome
```

---

Future versions may read many more.

---

Execution support is not required for discovery.

---

Portfolio Policy risk limits and liquidity requirements filter discovered opportunities before scoring.

---

# Step 6

Opportunity Scoring

Every opportunity receives a score.

---

Formula

```
score =
(APY × normalizedLiquidityScore × normalizedTrustScore)
-
(risk_penalty + gas_penalty)
```

---

Scoring remains deterministic.

---

No AI.

No machine learning.

No randomness.

---

# Example

Opportunity A

```
APY               = 7

normalizedLiquidityScore = 0.95

normalizedTrustScore     = 0.95

Risk Penalty      = 0.30

Gas Penalty       = 0.10
```

---

Opportunity B

```
APY               = 8.5

normalizedLiquidityScore = 0.70

normalizedTrustScore     = 0.65

Risk Penalty      = 0.90

Gas Penalty       = 0.15
```

---

Opportunity A may score higher despite lower APY.

---

# Step 7

Portfolio Construction

Portfolio Construction consumes:

```
Portfolio Policy

Opportunity Rankings

Eligible Opportunities
```

---

Top-N Selection

After scoring:

Opportunities are ranked.

---

V1 Rule

```
Maximum 3 active protocol allocations
```

per portfolio.

---

Reason

Simplicity.

Lower gas.

Easier explainability.

---

Example

```
1st Morpho

2nd Aave

3rd Moonwell
```

---

Everything else is discarded.

---

# Step 8

Portfolio Allocation

Selected opportunities receive weights.

---

V1 Method

Score-Proportional Allocation

---

Example

```
Morpho Score    = 95

Aave Score      = 90

Moonwell Score  = 85
```

---

Allocation

```
Morpho     35%

Aave       33%

Moonwell   32%
```

---

# Allocation Constraints

No protocol may exceed:

```
50%
```

of total portfolio value.

---

Reason

Risk concentration control.

---

# Stablecoin Concentration Rules

No single stablecoin may exceed:

```
80%
```

of portfolio value.

---

Applicable once multiple stablecoins exist in allocation universe.

---

# Gas Reserve Rules

Every portfolio maintains:

```
Operational Gas Reserve
```

---

Default:

```
1%
```

of portfolio value.

---

Minimum:

```
Protocol Configurable
```

---

Purpose

```
Rebalancing

Emergency Actions

Withdrawals
```

---

# Rebalancing Logic

Portfolio reviews occur:

```t
8h

24h

48h

72h
```

depending on policy.

---

Rebalancing only occurs if:

```
Expected Benefit
>
Expected Cost
```

---

This prevents unnecessary churn.

---

# Rebalance Threshold

Default

```
10% score improvement
```

required before allocation changes.

---

Configurable.

---

# Explainability Requirement


---

Reason

Every portfolio decision must be reconstructible.
